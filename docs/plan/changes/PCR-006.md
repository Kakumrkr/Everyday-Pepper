# PCR-006: Phase 8 operator feed — rule-based insights, drafts through the trust layer, a queued waitlist, commercial-email opt-out

- **Status:** Proposed (S34, 2026-10-24), waiting on the user's approval with the [Phase 8 playbook](../phase-8-playbook.md).
- **Date:** 2026-10-24
- **Plan version:** from 0.30 → to 0.31

## What changes and why
The [Phase 8 playbook](../phase-8-playbook.md) refines the approved operator-feed and waitlist design ([jobs-messaging-integrations.md](../../architecture/jobs-messaging-integrations.md), [data-model.md](../../architecture/data-model.md), [modules-and-templates.md](../../architecture/modules-and-templates.md)) in five places:

1. **Jobs** (playbook D-4). The architecture planned three BullMQ queues (`daily-briefing`, `insights`, `waitlist`). Now:
   - insights and the morning run are Postgres-driven `Periodic` passes through the read-only `job_scan` policy, like reminders (ADR-0025);
   - the waitlist keeps a queue, fed by an outbox-style row written in the cancellation's own transaction, so a cancellation is never lost and the offer goes out within 2 minutes (AC-W5-1).
   Why: insights tolerate minutes, and the existing passes already scale across businesses; only the waitlist has a latency promise.
2. **Rules find, the model writes** (D-2, D-3, D-8). Insights and the briefing text are deterministic. The model writes only rebooking drafts (subject and body); the domain sets recipient, times and links. Why: correct numbers, $0 for insight runs, and a smaller injection surface.
3. **Commercial-email opt-out** (D-9, D-10). Rebooking nudges are commercial email (CAN-SPAM). New `clients.email_opt_out_at`, a one-click unsubscribe (RFC 8058) and the business's identity in those emails; opted-out clients get no nudge. Transactional mail is unchanged.
4. **Waitlist offers** (D-6, D-7). A new `WaitlistOffer` record. Offers go to the top 3 matches at once, the first claim books through the availability engine, and the others are told the slot is taken. Ranking is window fit, then waiting time, then visit count.
5. **Chat tools and the dial** (D-11, D-12):
   - new tools `get_feed` (read) and `add_to_waitlist` (internal_write), with a new dial action `waitlist.change` (default notify, allows auto);
   - the S33 leftovers: `list_services_and_staff` v3 returns working hours, `find_availability` v3 applies `notBefore` to every day, instructions v6.

The roadmap's Phase 8 row is split into sessions S34–S38.

## Compatibility strategy
- All schema changes are additive migrations. The new columns are nullable or have defaults.
- The new dial action is additive. Older clients that don't know it never send it, and the Autonomy page lists it.
- Existing proposals, executions and emails are untouched. Nudges and offers use the existing actions and their defaults ("ask").
- Eval cases keep their format, with new optional fields. Tool version bumps expire older proposals as designed (ADR-0031).
