# PCR-004: S26b — the four tools owners will ask for in week one

## What changes and why
S26's review of the ten tools' guides found requests owners will make in the first week that the AI can't answer today:
1. **"When is Maria's next appointment?"** No tool lists a client's bookings: the AI can read a day by date, or a booking by its id, only.
2. **"What are my to-dos?" / "Mark the Maria call done."** The AI can add a to-do but not list or complete one.
3. **"Remove Jess's lunch block."** The AI can block time but not unblock it (only Undo, within its window).

The plan gains a session **S26b** before S27, so that S27's real-model evals cover these tools too. They never ship unevaluated. It adds four narrow tools:
- `find_client_bookings` (read): a client's upcoming and recent bookings, by client id;
- `list_todos` (read): the member's open to-dos (staff: their own);
- `complete_todo` (write, dial action `task.create`): marks a to-do done;
- `unblock_time` (write, dial action `time.block`): removes blocked time.

**Dial actions:** `complete_todo` and `unblock_time` reuse the existing actions `task.create` and `time.block`. The dial governs "to-dos" and "blocked time" as a whole, and their undo windows already fit. No new action, no migration of the dial's checks.

Client notes (`client_note.save` has no tool) belong to Phase 7 memory and are not part of S26b.

## Compatibility strategy
Additive only: new tools, new optional card fields, no schema migration of existing tables. Each new tool starts at version 1. No existing tool's version changes, so no stored proposal expires.
