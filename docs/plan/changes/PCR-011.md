# PCR-011: Phase 14 (SMS) before the rest of Phase 13, and S61 split in two

- **Status:** Approved (user, 2026-11-12, at the S61 brief: "let's start with your recommendation")
- **Date:** 2026-11-12
- **Plan version:** 0.36 → 0.37

## What changes and why

The rest of Phase 13 (S58a operate local, S57 deploy, S58b operate on the VPS, S60 pilot gate) leads up to the deploy, and the deploy needs a domain the user hasn't bought yet. The user wants to keep building in the meantime and chose **Phase 14 (SMS) now**: S61–S64 come before S58a, S57, S58b and S60. Every part of Phase 14 is built in sandbox mode first anyway (P1-5); going live needs the LLC and 10DLC registration (S64), which wait on the user just as the domain does.

At the brief, S61's row was too big for one context window (PCR-008): it mixed a booking-page screen, a provider adapter, an outbox channel, a signed webhook and the consent rules. It is split:

| Session | Target | Done when |
|---|---|---|
| **S61** | **SMS channel, backend** ([ADR-0065](../../adr/0065-sms-channel.md)): Twilio behind an `SmsSender` port, a sandbox sender that never leaves the machine, SMS as an outbox channel, consent records, STOP/START/HELP in the signed webhook's own request, quiet hours, delivery status, segment-aware text (GSM-7) | AC-X-57…63; STOP blocks the next send in the same request |
| **S61.2** | **SMS consent on screen**: the booking page's opt-in box (TCPA wording, unticked, never needed to book), SMS shown on the client's profile, the owner's SMS settings, the business's name in HELP, SMS's own AI disclosure | Screens at 375 px light and dark; the opt-in journey records consent |

The P1-9 line "the pilot starts after Phase 13, with email only" stays true in spirit: the pilot still starts at S60's gate. It now starts with SMS built in sandbox and switched on once 10DLC is approved.
