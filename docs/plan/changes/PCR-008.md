# PCR-008: Faster sessions: review before checks, each suite once, smaller sessions

- **Status:** Implemented
- **Date:** 2026-10-27 (after S41)
- **Plan version:** from 0.33 → to 0.34

## What changes and why
The user found sessions running long ("can you do a small audit… where we can reduce this without affecting the project", then "make a plan and work it out… without affecting the original flow"). S41's logs showed where the time went:

| What | Runs in S41 | Time |
|---|---|---|
| Full Playwright suite | 3 (8.9, 6.3, 6.3 min) + a stack rebuild each | ~22 min |
| Partial Playwright runs | 8 | ~8 min |
| `pnpm test:integration` | 1 | 7 min, with no backend code changed |
| A hand-written walkthrough script | timed out twice | ~15 min |
| A full context, then `/compact` | 1 | a restart mid-close |

CI then ran every suite again on the PR (~18 min). The waste is in **repeat runs and ordering**, not in the tests themselves, so no test is removed or loosened. The changes:

1. **Review before checks.** `/session-close` runs `/code-review` (and `/security-review` when needed) first, fixes, then the full checks. Before, the review came after the checks, and its fixes sent every suite round again.
2. **A red step re-runs only the failing tests**, then goes on. Before, "a fix re-runs that step" meant the whole suite. CI still runs every suite once on the PR.
3. **`pnpm test:integration` only when the session changed code it runs** (`packages/` other than `ui`, `apps/api`, `apps/worker`, migrations). Screens-only sessions skip it locally and say so in the PR; CI runs it.
4. **The walkthrough uses the screenshot baselines** (375/412/1280 px × light/dark, already in `e2e/tests/__screenshots__/`) plus one changed flow walked at 375 px, instead of re-taking every screen by hand.
5. **Sessions sized to one context window.** The brief proposes a split when a target moves more than about four screens or mixes screens, backend and tooling. **S42 is split**: S42 Calendar and Clients; **S42.2** Services, Team, Autonomy, What I know, Waitlist. (Named S42.2, not S42b, so it is not mistaken for a recording half; S43–S76 keep their numbers.)
6. **Decisions written once:** in full in `decisions.md`, a one-line pointer in STATUS "Recent decisions"; "Last sessions" entries 3–4 lines; checkpoints one line per task.

Estimated saving: 25–40 minutes per screens session, more when a check fails.

## Compatibility strategy
Process only. Every test still runs in full once per session, locally or in CI. The one trade-off: a failure that a skipped local integration run would have caught now shows in CI, costing one extra CI run (~18 of the 2,000 monthly minutes). For screens-only sessions that risk is small (no code the integration tests run has changed).

## Tests proving no regression
No product code or test changes. The suites stay as they are; CI's jobs are unchanged. This PR is docs-only, so CI skips its slow jobs.
