## What changes and why
The [Phase 7 playbook](../phase-7-playbook.md) refines the approved memory design ([memory.md](../../architecture/memory.md), [data-model.md](../../architecture/data-model.md)) in five places:

1. **Episodic recall on demand** (playbook D-3). memory.md's recall step 2 ("top-k episodic items by embedding similarity") ran every turn. Now it is a read tool, `search_memory`, that the model calls when the past matters. Facts still recall deterministically, attached to the entity a tool returns (D-2). Why: no embedding call or extra tokens on most turns, and a smaller injection surface. An allergy never depends on a similarity score.
2. **Exact vector search in V1** (D-4). data-model.md named an HNSW index. Per-business corpora are small, and exact search inside the tenant and member returns 100% of matches without filtered-ANN pitfalls. HNSW with pgvector 0.8 iterative scans is added when a business passes about 20k episodes.
3. **Forget everywhere** (D-13, D-8). Deleting the fact row alone would not meet AC-W7-2: the value would remain in conversation history (sent again when a chat continues), in the append-only proposal and execution records, and in episodes. Now:
   - values live only in the memory tables, and trust records and stored tool answers refer to them by id;
   - one `forgetFact` transaction deletes the row, its Undo-window previous value, its embedding and the episodes that name it;
   - the same transaction scrubs the stored conversation text that quoted it, through one narrow, audited redaction path in the append-only conversation guard.
4. **Learned rules through the dial** (D-10). A new autonomy action `rule.change` is locked to "ask", like the bulk lock. A learned rule maps onto the existing rule types or working hours, and an owner or manager approves it.
5. **Additions:**
   - visit notes as facts on a `booking` subject (D-14);
   - template config for warnings and visit-note keys;
   - a business-level pause switch (D-15).

The roadmap's Phase 7 row is split into sessions S29–S33.

## Compatibility strategy
- All schema changes are additive migrations.
- The new dial action is additive. Nothing can set it to anything but "ask", and older clients that don't know it never send it.
- Existing conversation messages are untouched. Only messages that hold a forgotten value are redacted, and only through `forgetFact`.
- Eval cases keep their format, with new optional fields.

## Tests proving no regression
- Must stay green:
  - `pnpm check`;
  - `pnpm test:integration` (incl. the cross-tenant isolation suite at 100%);
  - the hostile fake at 100%;
  - Playwright;
  - the Phase 6 eval sets replayed in CI.
- After the S33 re-record, the Phase 6 gates still hold: scheduling ≥ 90%, and safety, permissions and autonomy at 100% at pass^3.
- New tests:
  - `forgetFact` leaves the value nowhere in storage;
  - the same conversation continued after a forget never sends the value;
  - the redaction path can't be reached any other way;
  - `decideAutonomy` properties with `rule.change`.
